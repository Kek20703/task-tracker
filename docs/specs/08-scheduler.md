# Этап 8. Scheduler

> Статус постановки: `утверждена`. Дата утверждения: 2026-11-12. Ветка: `feature/scheduler`.
> После утверждения изменения — только отдельным решением.

## Цель

Раз в сутки находить пользователей, у которых за предыдущий календарный день есть выполненные
задачи или остались незавершённые, запрашивать отчёт у summarization-сервиса и отправлять письмо.

## Границы

Входит:

- новый Gradle-проект `task-tracker-scheduler`;
- расписание раз в полночь с часовым поясом из окружения;
- чтение задач из Postgres, только на чтение;
- Kafka RPC к summarization-сервису;
- отправка письма в `EMAIL_SENDING_TASKS`;
- ручной запуск через тест/флаг для проверки.

Не входит:

- запись в базу backend;
- собственные миграции — схемой владеет backend;
- генерация отчёта — этап 7;
- повторная доставка письма при сбое — долг outbox.

## Расписание и период

- Cron `0 0 0 * * *`, часовой пояс `SCHEDULER_ZONE` (по умолчанию UTC).
- Период — предыдущий календарный день в этом поясе: `[начало вчера, начало сегодня)`.
- Пользователь попадает в рассылку, если есть задача с `completed_at` в периоде
  **или** задача со статусом `TODO`.
- Для отчёта берутся задачи: выполненные в периоде + все `TODO` этого пользователя.

## Контракты

- **Kafka RPC:** запрос в `SUMMARIZATION_REQUESTS`, ответ в `SUMMARIZATION_RESPONSES`;
  DTO и `requestId` совпадают с этапом 7.
- **Письмо:** `EMAIL_SENDING_TASKS`, JSON `{"to","subject","text"}` без заголовков типа.
  Тема — «Итоги дня в Task Tracker», текст — отчёт и период.
- **Таймаут RPC:** `SUMMARIZATION_TIMEOUT`, по умолчанию 30 секунд.
- **Сбой RPC:** отправляем письмо с простым шаблонным отчётом, а не теряем его.

## Конфигурация

- `KAFKA_BOOTSTRAP_SERVERS`, `POSTGRES_*`, `SUMMARIZATION_DB` (не используется scheduler) и
  `POSTGRES_DB` — подключение к базе backend.
- `SCHEDULER_ZONE`, `SCHEDULER_CRON`, `SUMMARIZATION_TIMEOUT`.
- `SUMMARIZATION_REQUESTS_TOPIC`, `SUMMARIZATION_RESPONSES_TOPIC`, `EMAIL_SENDING_TASKS_TOPIC`.

## Поведение при сбоях

- Summarization недоступен/таймаут — шаблонный отчёт, письмо уходит.
- Email-sender недоступен — ошибка Kafka логируется, расписание не падает.
- Ошибка БД — логируется; следующий запуск попробует снова.
- Повторный запуск за тот же период не создаёт дублей в БД scheduler (своей БД нет).

## Критерии готовности

- [ ] Scheduler стартует без summarization/email-sender.
- [ ] За предыдущий день выбираются нужные пользователи и задачи.
- [ ] Отчёт запрашивается по Kafka RPC; при таймауте используется шаблон.
- [ ] Письмо уходит в `EMAIL_SENDING_TASKS` с корректным JSON.
- [ ] `ArchitectureTest`, тесты Postgres/Kafka, покрытие не ниже 70%.
- [ ] Ручной запуск через `scheduler.run-on-startup=true` или тест.

- [ ] Интеграционный тест Postgres + Kafka.
