# Этап 6. Приветственное письмо

> Статус постановки: `черновик`. Ветка: `feature/welcome-email`.
> Нужно утвердить до начала кода. После утверждения изменения — только отдельным решением.

## Цель

После успешной регистрации backend отправляет приветственное письмо через Kafka, не задерживая
и не ломая регистрацию, если Kafka недоступна.

## Границы

Входит:

- producer в `task-tracker-backend` для топика `EMAIL_SENDING_TASKS`;
- DTO `EmailMessage` (`to`, `subject`, `text`) в backend, совпадающий с DTO email-sender;
- публикация сообщения после фиксации транзакции регистрации;
- тесты: контракт сообщения, регистрация при недоступной Kafka, сквозной прогон с Mailpit;
- `.http`-коллекция уже покрывает регистрацию, менять её не нужно.

Не входит:

- повторные попытки и DLT в backend — это уже делает email-sender;
- другие письма (сброс пароля, отчёты);
- изменение контракта email-sender, кроме синхронизации DTO;
- outbox и гарантированная доставка при недоступной Kafka — кандидат в долги.

## Контракты

- **Kafka:** топик `EMAIL_SENDING_TASKS`. Ключ сообщения — email пользователя. JSON без заголовков
  типа: `{"to": "...", "subject": "...", "text": "..."}`.
- **DTO:** `record EmailMessage(String to, String subject, String text)`. Копия DTO email-sender;
  расхождение ловится тестом на обеих сторонах.
- **Письмо:** `to` — нормализованный email; `subject` — «Добро пожаловать в Task Tracker»;
  `text` — короткое приветствие без персональных данных, кроме email.
- **API:** `POST /auth/register` не меняется: успех — `201` и токен, занятый email — `409`,
  невалидные данные — `400`.

## Данные и миграции

Нет.

## Конфигурация

- `KAFKA_BOOTSTRAP_SERVERS` — по умолчанию `localhost:29092` для запуска из IDE.
- Producer: `StringSerializer` для ключа, `JacksonJsonSerializer` для значения,
  `spring.json.add.type.headers=false`.
- `max.block.ms` — не больше 1 секунды, чтобы недоступная Kafka не задерживала ответ регистрации.

## Поведение при сбоях

- Kafka недоступна или отправка не удалась: регистрация всё равно успешна, ошибка пишется в лог.
- Письмо в этом случае может потеряться — это осознанное упрощение этапа, outbox отложен.
- Ответ регистрации не ждёт фактической доставки сообщения в брокер дольше ~1 секунды.

## Критерии готовности

- [ ] Регистрация при остановленной Kafka отвечает `201` и не дольше ~1 секунды сверх обычного.
- [ ] При работающей Kafka письмо появляется в Mailpit с корректными `to`, `subject`, `text`.
- [ ] Сообщение в топике — JSON без заголовков типа; DTO совпадает с email-sender.
- [ ] Есть тест на формат сообщения и тест регистрации при недоступной Kafka.
- [ ] `ArchitectureTest` проходит, покрытие не ниже 70%.

## Проверки

- [ ] Интеграционный тест backend с Kafka в Testcontainers.
